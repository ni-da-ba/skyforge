# Minecraft target adapter status

Current target path: **minecraft-adapter-0.5** for the v0.14 first-principles Guild branch.

The acceptance boundary is now:

```text
architecture role/module + geometric orientation
    -> backend-neutral RealizationIntent IR
    -> Minecraft capability resolver
    -> explicit default states
    -> pane/fence/stair neighborhood realization
    -> shape/support checks and bounded target repair
    -> realized-geometry correctness gate
         - recessed-aperture closure
         - operational portal clearance
         - partial-detail physical contact
    -> explicit bounded block-entity NBT
    -> structure-template NBT
```

The v0.14 target-lowering tests deliberately erase every upstream Minecraft resource location before
adapter resolution. Passing this test is the proof that the Minecraft palette is no longer an
architectural authority.

## v0.5 human-gate response

The first in-engine v0.14 inspection accepted the architectural composition and exposed only bounded
target-medium defects: recessed panes were not sealed against front-plane jambs, the freight opening
had a calcite partition column tight against its interior margin, and the waiting-bench fence backs
were visually unsupported above half-height slabs.

The v0.5 realized-geometry pass corrects those defects without changing the architectural digest:

- 21 jamb-backed timber aperture returns are inserted only where a recessed pane has an empty edge
  cell and a structural jamb/post exactly one block diagonally toward the exterior;
- 3 calcite partition cells at the freight opening are removed to restore the bounded service-portal
  margin, while the transom-height cell is subsequently replaced by a timber aperture return;
- 6 unsupported waiting-bench fence-back cells are omitted because their connected fence components
  have no physical contact with the half-height seat slabs or another anchored target shape;
- 222 remaining slab/fence cells are checked by component-level target-shape contact;
- 7 working service-door cells are checked for direct interior clearance.

Canonical target cell count changes from 1,885 architectural cells to 1,897 realized Minecraft cells.
The architecture digest remains
`cbb02ebaea269bbb836d96fe11edf2ac2716fbfd0e7bac8b963fa9430b2991b8`.

Automatic repair remains deliberately narrow. Ambiguous clearance or support failures reject the
realization rather than inventing geometry.
