## Recommended wording by audience

### Nontechnical / general introduction

> Skyforge is a world-building engine that begins with what a place is supposed to be, then makes the terrain and its surrounding systems follow from that identity. The first working version realizes those worlds inside Minecraft, where the islands are full three-dimensional objects with real undersides, ecology, persistence, and reproducible geometry.

### Recruiter / hiring manager

> Skyforge is an architecture-first procedural world-synthesis project. It separates a deterministic backend-neutral world model from the runtime that realizes it, then proves that boundary through exact finite-volume terrain, Minecraft lifecycle integration, persistence, reproducible evidence, and a growing semantic stack for geology, hydrology, ecology, resources, and regional composition.

For personal-authorship contexts, prefer wording such as **“architected and led development of”** when that better represents the project’s AI-assisted multi-agent implementation process than implying every line was personally typed by one developer.

### Technical engineer

> Semantic descriptors compile through versioned recipes into immutable procedural graphs and deterministic scalar fields. Those fields define exact finite 3-D ownership. The NeoForge backend consumes that neutral output and adapts Minecraft lifecycle behavior without making Minecraft the owner of the terrain model.

### Procedural-generation specialist

> The differentiator is not another noise stack. Skyforge is built around semantic hierarchy, explicit provenance, provider-neutral morphology, volumetric ownership, deterministic evaluation, and increasingly coupled world-system evidence. Five primary morphology families already compile through the same production path and have accepted exact Minecraft carriers at the SMALL / seed-skyforge boundary.

### Minecraft/player-facing

> Skyforge is building a Minecraft world where floating-island geography is meant to have consequences. Different landforms, resources, ecology, travel, industry, and eventually settlements and routes are intended to emerge from one authored world model instead of being unrelated random layers. The project is still pre-release, but the core terrain and several Minecraft integration systems are already working.

## One-minute progression

A reliable general-audience order is:

1. **Meaning:** “The generator starts from what kind of place this is.”
2. **Shape:** show five morphology identities.
3. **Depth:** orbit underneath one island; explain it is a finite 3-D volume.
4. **Reality:** show that same class of authored terrain inside Minecraft.
5. **Life:** show accepted forest/taiga ecology.
6. **Proof:** mention deterministic identity + save/reopen.
7. **Direction:** label Bootstrap Province as the next convergence target, not current capability.

## Audience-specific traps

- **General audience:** technical detail can accidentally make the project sound smaller. Explain consequences first, mechanism second.
- **Recruiters:** “Minecraft mod” can hide the architecture/systems work. State the backend-neutral engine first, then use Minecraft as proof of integration.
- **Engineers:** inspirational prose without exact boundaries will reduce credibility. Preserve determinism, ownership, module separation, and accepted-vs-roadmap status.
- **Procgen specialists:** “semantic” cannot be empty branding. Point to descriptors, recipes, provider-neutral compilation, provenance, exact volumes, and deterministic corpora.
- **Players:** do not sell future gameplay as present. Say what can already be shown, then explicitly label the intended Bootstrap Province experience.
