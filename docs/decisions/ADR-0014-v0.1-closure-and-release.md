# ADR-0014: v0.1 architecture-proof closure and release

**Status:** Accepted  
**Date:** 2026-08-03  
**Ticket:** SF-IMP-0010

## Context

Sprint One implemented the v0.1 vertical slice from a semantic island descriptor through recipe
compilation, typed graph evaluation, deterministic sampling, fixed-seed evidence, and visual
review. The closure audit must reconcile the original proposed baseline with what the passing code
and corpus actually prove, without inflating the release into a content-complete generator.

The audit found no failed acceptance gate. It did find stale bookkeeping: the baseline still called
itself proposed, the first five completed implementation steps were unchecked, and the graph
contract's upper-bound list could be misread as a list of implemented node kinds.

## Decision

1. Accept `Skyforge_Architecture_Baseline_v0.1` as the contract for the released architecture
   proof.
2. Release the proof as engine version `0.1.0` after its protected-`main` Java 25 build passes.
3. Treat the gate trace and corpus facts in `docs/releases/Skyforge_v0.1.0_Release_Record.md` as the
   durable closure record.
4. Record the exact implemented graph-node set: constants, coordinates, basic arithmetic, and the
   versioned seeded planar value signal. The broader convenience-node list was a permitted ceiling,
   not a completed feature claim.
5. Preserve canonical graph schemas 1 and 2, seed derivation version 1, signal version 1, recipe
   versions 1 and 2, and the `fixed-seed-island-v1` corpus as the v0.1 identity boundary.
6. Require the `v0.1.0` tag to identify the exact protected-`main` commit whose push build passes;
   do not tag the pull-request head or a merely pre-merge build.
7. Begin v0.2 with composition and secondary morphology. Backend integration and optimization do
   not become the default next step merely because the first vertical slice is complete.

## Evidence disposition

- All six `SF-KER` and all nine `SF-ISL` gates are traced to named tests or build tasks.
- The six-member 1024 by 1024 corpus pins 49 canonical artifacts and evaluates 6,291,456 height
  samples per full run.
- Every seed has one connected land component, zero boundary land samples, and the same canonical
  land-mask checksum.
- Java 25 CI compiles with `-Xlint:all -Werror`, executes 85 JUnit tests, enforces backend
  independence, regenerates the corpus, and publishes the review atlas.
- Benchmark timing remains environment-qualified and nonnormative.

## Consequences

- v0.1 is a reproducible architecture proof, not a promise of naturalistic final terrain.
- Review PNGs remain explanatory projections; canonical grids, JSON, CSV, statistics, and hashes
  remain the numerical authority.
- Any future change to the frozen identity boundary requires an explicit schema/corpus/version
  decision and an explanation of the observed drift.
- The next baseline may add capability, but it may not silently weaken v0.1 determinism,
  inspectability, backend independence, or semantic ownership.
